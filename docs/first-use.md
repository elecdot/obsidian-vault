# First-use Walkthroughs

These are design examples through Q63, not the author's research records
or a claim that the described tools already work. They illustrate accepted
relationships, entry defaults, and naming behavior without prescribing the
author's prose organization. No illustrated content files have been created.
Each internal target below is assumed to exist in the hypothetical scenario
before a structural relationship points to it.

Source paths are readable illustrations of the accepted layout, not a final
Zotero identifier or output-path decision. Technical questions in example
Notes are prompts for learning, not researched conclusions.

## AI Systems: A Question Inside an Activity

Assume an authored Domain entry at `domains/ai-systems.md` and a hypothetical
paper-reproduction Activity at
`activities/kernel-paper-reproduction/introduction.md`. The Activity already
has this relationship, chosen for this example:

```yaml
kind: activity
domains:
  - "[[domains/ai-systems]]"
```

While comparing two runs, the author wants to preserve a question before
deciding how much to develop it. A contextual capture creates
`inbox/run-comparison-question.md` with this illustrative content:

```markdown
---
kind: note
activities:
  - "[[activities/kernel-paper-reproduction/introduction]]"
---
# Run comparison question

What do I need to compare before treating these two runs as evidence
about the same question?

Keep the relevant run records or source locations here while the context
is still available.
```

The final sentence illustrates a capture cue, not a fabricated run record.
Creation supplies the chosen Activity association; it does not copy every
Domain associated with that Activity. The Activity can discover the Capture
through the existing incoming-relationship model without adding a link to
its authored Guide.

On returning to the question, the author can continue the same Note. If it
is worth retaining as Activity-specific work, it can be organized into that
Activity with reference maintenance. A useful passage can receive an
author-selected refinement marker. Neither association nor moving the file
asserts that its explanation is mature.

If later learning produces an independently reusable explanation, the author
can develop a separate `knowledge/` Note with provenance and meaningful
connections. The agent can help inspect reasoning and organize the result;
it does not turn an unanswered suggestion into the author's conclusion.

### Q61: Returning Through the Domain

The Capture above has no direct `domains` relationship. Its route into
AI Systems is the associated Activity. The accepted initial presentation
shows directly associated Notes and related Activity entries; enter the
Activity to see its contextual Notes.

Both relationships may also be written explicitly on the same Note:

```yaml
kind: note
activities:
  - "[[activities/kernel-paper-reproduction/introduction]]"
domains:
  - "[[domains/ai-systems]]"
```

With this metadata the Note appears in both direct association views.
These are independent scopes, not mutually exclusive choices. The author
can choose a direct Domain association without copying all of the Activity's
Domains. The [relationship contract](metadata.md#relationships) owns this rule.

A separate one-hop contextual Note list remains a possible extension if
seeing those records on the Domain page becomes useful.

This choice does not establish inheritance across overlapping Domains.
A Guide can explain routes to related Domains without treating every link
as membership or recursively collecting their entire contents.

Official Bases interfaces can express the one-hop lookup, but cross-file
`file.properties` does not automatically refresh when vault content changes.
Such an extension needs a verified refresh strategy; the effect of relationship
edits cannot be assumed immediately visible. Neither presentation has yet
been implemented or tested in this vault. See the
[relationship-view evidence](design-questions.md#domain-context-query-evidence).

## Reading: A Source Before an Activity

Use *Linear Algebra Done Right* as an illustrative reading context, without
committing the author to a study schedule or inventing book-specific content:

```text
sources/linear-algebra-done-right/
  source.md
  reading-notes.md
```

The Source record describes or holds the selected material. If generated by
an importer, it belongs to that importer as a whole. The personal reading
Note is separately authored; its minimal relationship is:

```yaml
kind: note
sources:
  - "[[sources/linear-algebra-done-right/source]]"
```

No Activity or Domain is required to start writing. A draft may keep a
question such as “Can I explain linear independence using a different
example?” together with a precise source location and the author's attempt.
It need not label itself `format: reading` or claim a finished explanation.

If deliberate study later needs goals, exercises, or coordination, create an
Activity entry that links the existing reading Note. New Activity-specific
work can live there while the earlier reading Note keeps its location.
Independently reusable explanations can become knowledge Notes when useful.

### Q62: The Default Reading Record

Q62 clarified a tool default, not a new content-model rule. The reading
entry should help reopen relevant existing personal writing rather than
automatically create a new file each session. A Source can have several
reading Notes, and creating a new one remains available when useful.

For this example the author can continue `reading-notes.md`, organizing the
writing by related questions or sections. Dated session records, separate
derivations, and chapter Notes are also valid choices. Coherence and useful
boundaries remain author judgments; neither a compulsory chapter tree nor
a one-Note-per-Source constraint follows from the default. See
[reading entry defaults](design.md#reading-entry-defaults-and-writing-freedom).

At a useful stopping point, a brief sentence can record where the reasoning
stands and what to examine next. This is contextual writing, not a mandatory
set of progress fields or a second copy of Zotero's reading position.

## Q63: Capturing Before an English Name Is Ready

The ordinary naming convention remains one readable English name at creation.
Q63 accepts an exception for quick capture: when the author has a useful
question but no good English name yet, an omitted name yields a provisional
filename such as `capture-2026-10-04-213045.md`. A chosen meaningful name
still works. The [naming contract](metadata.md#quick-capture-names) owns this
exception.

The example timestamp is illustrative, not an event record. Concrete creation
must avoid collisions without overwriting an existing file. When organizing
a retained Capture, supply a useful English name and maintain any references
as part of the rename. A new file-ID field or global title synchronizer is
not required by this convention.

## Support Made Concrete by These Walkthroughs

| Action | Needed support | Boundary to verify |
| --- | --- | --- |
| Capture in a known context | A creation action carrying the selected relationship and a clear destination | No unrelated inheritance, overwrite, or rewriting of the entry's Guide |
| Return through a Domain or Activity | Direct relationship views and related Activity entry points | Captures remain discoverable; indirect context stays distinguishable from direct association |
| Continue reading | An easy route to the authored reading Note and its Source | Reopening preserves writing; re-import does not own personal Notes |
| Select something to develop | In-place refinement markers and a shared discovery entry | The author adopts candidates; source context survives development |
| Maintain the conventions | Registered field meanings, consistent creation output, structural audit, and agent guidance | Allowed omissions remain valid; semantic suggestions are not structural errors |

The decisions govern the needed support, including tools and skills. Runtime
verification and exact creation prompts follow; this walkthrough is a review
of the design, not evidence that those capabilities have been delivered.
