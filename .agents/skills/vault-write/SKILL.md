Help the author express and develop their own understanding. Read the target,
its relevant sources, and [authorship guidance](../../../docs/design.md#authorship-and-collaborative-writing).
Consult [metadata](../../../docs/metadata.md) when creating a Note or changing
its relationships; use the existing purpose rather than infer it from the
currently open file alone.

Work from the author's outline, questions, or key claims. If a gap changes
the argument, ask a focused question or help examine the source. Label
assistant-supplied reference material; fluency does not establish adoption.
Improve wording directly when meaning is already clear. The author's
write-better-english skill can help when available, but its absence does not
block ordinary editing.

Use the supported [creation operations](../../../docs/operations.md#command-line-operations)
for a new Note, including a preview when placement is uncertain. Existing
authored Notes can be edited normally within the request. A correct Source
reference may cite an earlier personal Note without changing its kind.

Let coherence and independent reuse guide note boundaries. Reading templates
offer a return point, not a mandatory chapter/session structure. Keep the
author's uncertainty and source context visible; record refinement markers
when the request or response adopts them.

Report the changes, meaningful unresolved reasoning, and actual checks.
Avoid assigning understanding, lifecycle state, or new Tasks on the basis of
an unanswered suggestion.
